# MCP gateway research, 12 November 2026

Scope: protocol compatibility, retries and durable execution for the finance investigation. Protocol text and SDK documentation below are primary sources; observations about this repository are from its source and lockfile. This is not a claim of complete conformance or an external interoperability certification.

## Compatibility

- The 2025-11-25 Streamable HTTP transport permits a JSON response to a POST and does not require an SSE stream for server messages: GET can return 405. Clients must support JSON and SSE and send both in `Accept`; later requests carry the negotiated protocol version. A session ID is optional. [MCP transport specification](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)
- The gateway creates a stateless `WebStandardStreamableHTTPServerTransport` with JSON responses. The official installed SDK `Client` and `StreamableHTTPClientTransport` completed initialize, list and call in the in-process test `apps/api/test/mcp.test.ts`; that test does not prove interoperability across independent SDK implementations, proxies, hosted deployments, or every protocol version.
- The latest 2026-07-28 transport changes the request metadata and header requirements and changes the meaning of closing an SSE stream. It is not interchangeable with the earlier transport merely by changing a version string. Keep the tested version behavior until migration is explicitly implemented and tested. [2026-07-28 transport](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/basic/transports/streamable-http.mdx)
- Tool execution errors belong in tool results with `isError: true` and actionable feedback; structured JSON should also be serialized as text for backward compatibility. The server must validate inputs and access and rate-limit invocations. [MCP tool specification](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

## Retry and durability

- In 2025-11-25, disconnect is not itself cancellation; SSE event IDs and replay are optional, and resumption uses `Last-Event-ID`. This is transport-level message redelivery, not a guarantee that a paid tool is executed exactly once. The gateway uses JSON responses and does not implement SSE event replay. [Transport resumability and cancellation](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)
- Repository behavior: the idempotency key binds the tool and input; the kernel records a tool call and transactionally commits the charge, but the meter does not persist the output. A replay returns `idempotency_conflict`, so it prevents another charge but cannot recover a lost successful response. If a provider succeeds and the transaction rolls back or the process fails before commit, the same input may execute again without a corresponding first charge. This is not durable result replay or exactly-once provider execution. See `apps/api/src/mcp.ts`, `apps/api/src/meter.ts`, and `packages/kernel/src/usage.ts`.
- A robust design needs a durable, lease-scoped invocation record binding key, input hash, state, result and receipt, atomic with the financial commit where possible. For external side effects, use provider idempotency where supported and reconcile ambiguous outcomes; an application database transaction cannot alone guarantee exactly-once behavior at a remote provider. This is an engineering inference, not a capability provided automatically by MCP.
- MCP 2025-11-25 describes experimental tasks as durable state machines for polling and deferred result retrieval, with capability and per-tool negotiation, terminal result retrieval and a server-selected TTL. Task records can expire. The protocol alone does not create a durable worker, atomic accounting, or indefinite receipts. [MCP tasks specification](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/tasks)

## Security and version check

- The 2025-11-25 specification requires validation of an `Origin` header when present. The SDK transport defaults `enableDnsRebindingProtection` to false and the gateway does not configure that SDK option. Instead, the gateway rejects origins outside its explicit allowlist before authentication; with no allowlist it rejects every present Origin. Its focused test checks allowed, absent, malformed and untrusted origins. The local server also binds loopback. This is not a full conformance audit. [MCP transport security](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)
- The lockfile and locally installed SDK resolve `@modelcontextprotocol/sdk` to 1.32.2. The official cross-origin redirect advisory affects versions before 1.32.0 and says 1.32.0 fixes that issue; this check does not assess all advisories or every dependency. [GHSA-6prh-2h8m-c8cw](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-6prh-2h8m-c8cw)
